개발자 라이언, 클로드로 움직이는 설명 그림 만드는 ‘아나토미’ 공개

개발자 라이언이 클로드의 코딩 도구에서 움직이는 설명 그림을 만드는 ‘아나토미(Anatomy) 1.0’을 공개했다. 기계의 부품을 펼치거나 손잡이를 돌려 내부 원리를 보여 주는 그림을 만드는 도구다. 한국 시간 10월 11일 나온 첫 정식 릴리스에는 그림 제작 규칙과 완성된 예제 여덟 개가 담겼다.

아나토미는 앤트로픽이 클로드에 새로 넣은 기본 기능이 아니라, 외부 개발자가 공개한 추가 도구다. 사용자는 클로드 코드에 이것을 연결한 뒤 무엇을 설명할지 요청한다. 결과는 글 위에 붙이는 정지 사진부터, 독자가 마우스나 키보드로 조작하는 웹페이지까지 이어진다.

예를 들어 커피 기계의 옆면을 열고 물이 지나가는 길을 보여 주고 싶다고 하자. 공식 안내에는 보일러·펌프·관을 넣고 커피를 뽑을 때 물이 흐르는 그림을 요청하는 예시가 있다. 독자는 완성된 기계의 겉모습뿐 아니라 안에서 무엇이 먼저 움직이는지도 볼 수 있다. 이런 용도가 프로젝트가 소개하는 설명 그림의 방향이다.

그림 한 장보다, 원리를 보여 주는 작은 장치

일반적인 이미지 생성에서는 원하는 장면을 말하고 완성된 그림을 받는다. 아나토미가 만드는 결과는 코드로 그린 부품과 조작 기능을 함께 갖는다. 공개 안내는 독립된 HTML 웹페이지, 선과 도형으로 구성한 SVG 파일, 웹서비스에 넣는 React 구성요소를 결과 형식으로 제시한다.

SVG는 점과 선의 위치를 숫자로 기록하는 그림 형식이다. 그래서 부품의 위치를 바꾸거나 특정 부분만 움직이게 만들기 좋다. 물이나 불빛처럼 선으로 표현하기 어려운 효과에는 브라우저에서 입체 그래픽을 그리는 WebGL을 선택적으로 섞는다. 실제 입체 회전 기능은 아직 베타다.

이 작업을 클로드에 가르치는 묶음이 ‘스킬’이다. 클로드 코드의 공식 설명에 따르면 스킬은 반복해서 사용할 지침과 필요한 파일을 담는다. 매번 긴 제작 기준을 복사하는 대신, 관련 작업을 요청할 때 클로드가 그 기준을 읽게 하는 방식이다. 아나토미는 그 안에 그림 제작과 검수 절차를 넣었다.

코드로 남는 그림은 수정 방식도 다르다. 웹 표준 설명서 MDN은 SVG를 크기를 바꿔도 선명하게 그릴 수 있고, 그림 속 글자를 직접 수정할 수 있는 형식으로 설명한다. 제목의 철자를 고치려고 그림 전체를 다시 생성할 필요가 줄어드는 이유다. 웹페이지의 조작 기능은 그 그림에 별도의 동작 코드를 붙여 만든다.

이 차이는 게시 장소를 고를 때도 중요하다. 정지 이미지로 저장한 장면에서는 독자가 손잡이를 돌릴 수 없다. 직접 조작하는 설명을 제공하려면 그 기능을 실행하는 웹페이지나 구성요소를 함께 제공해야 한다. 같은 그림이라도 블로그 본문에서 체험하게 할지, 수업 자료에 한 장면만 넣을지에 따라 준비할 결과물이 달라진다.

모양과 숫자가 같은 움직임을 설명하게 한다

설명 그림은 움직이기만 해서는 부족하다. 바늘이 가리키는 값과 옆에 적힌 숫자가 서로 다르면, 보는 사람은 무엇을 믿어야 할지 알 수 없다. 아나토미의 동작 설계 문서는 움직이는 부품과 표시 숫자가 같은 계산 결과를 사용하도록 정한다. 설명 문구도 동작이 끝나기 전에 완료됐다고 표시하지 않게 한다.

독자가 직접 조작하는 과정도 따로 다룬다. 마우스로 가리키는 행동이 없는 휴대전화에서는 누르기로 반응하게 하고, 그림을 만지다가 페이지를 아래로 읽는 동작도 유지한다. 화면에서 벗어난 그림은 계속 움직이지 않도록 설계한다. 장식이 독자의 읽기를 방해하지 않게 하는 규칙이다.

움직임을 줄이도록 설정한 독자에게는 부품이 천천히 이동하는 연출 대신 결과 위치를 바로 보여 준다. 조작 결과는 남기고 불필요한 흔들림을 줄이는 방식이다. 제작자가 보기 좋은 움직임과 독자가 편하게 읽는 움직임을 함께 고려한 부분이다.

예쁘게 그린 뒤에도 확인할 일이 남는다

아나토미에는 완성 화면을 여러 크기로 찍고, 부품의 연결 부위를 확대해 살펴보는 검수 도구가 포함돼 있다. 검수 기준은 관이 다른 부품을 뚫고 지나가는지, 선이 허공에서 끝나는지, 앞쪽 물체가 뒤쪽처럼 그려졌는지 등을 확인한다. 정지했을 때뿐 아니라 움직이는 중간 모습도 검사 대상으로 삼는다.

자동 검사는 기록된 도형과 규칙을 검사한다. 설명하려는 과학 원리나 기계의 실제 사양까지 모두 검증해 주지는 않는다. 예를 들어 수업용 그림에 넣은 압력 수치가 틀렸다면 선이 깔끔하게 연결돼도 내용은 틀리다. 교육자는 움직임의 완성도와 설명의 정확성을 따로 보는 편이 좋다.

따라서 처음부터 복잡한 기계 전체를 맡기기보다, 독자가 이해할 한 가지 관계를 정하는 편이 쓰임새가 분명하다. 예를 들어 ‘손잡이를 돌리면 어느 부품이 함께 움직이는가’처럼 목표를 좁힐 수 있다. 이는 편집부의 활용 예시다. 움직임이 전달할 핵심을 먼저 정하면 보기 좋은 부품을 늘리는 데 작업이 흐르는 것도 줄일 수 있다.

공개 코드의 사용 허락과 클로드 비용은 별개

프로젝트 코드는 MIT 라이선스로 공개됐다. 해당 코드의 사용·수정·배포·판매를 허용하며, 복사본이나 상당한 부분을 배포할 때 저작권과 허가 문구를 포함하도록 한다. 개발자는 소프트웨어의 품질이나 특정 용도에 대한 보증도 제공하지 않는다.

그 코드를 이용해 그림을 만들 때 쓰는 클로드 비용은 따로다. 클로드 코드의 비용 안내는 구독에 포함된 사용량과 API 사용량 과금을 구분한다. 기존 구독으로 실행하면 해당 구독의 한도를 사용하고, API로 연결하면 사용한 글의 양에 따라 비용이 발생한다. 그림 제작 중에도 해당 계정의 구독 한도와 API 과금 조건이 적용된다.

작업 시간도 필요하다. 개발자는 세밀한 부품 제작과 검사에 긴 작업 시간이 들 수 있다고 안내한다. 특히 3D 기능은 초기 시험 단계라 복잡한 그림의 성능을 별도로 확인할 필요가 있다. 빠르게 한 장을 뽑는 용도보다, 여러 번 읽을 설명 자료를 다듬는 용도에 더 가깝다.

블로그나 수업에서의 활용 가치는 여기서 선명해진다. 글은 원인을 설명하고, 조작하는 그림은 독자가 그 변화가 일어나는 순간을 직접 살펴보게 한다. 모든 문단에 움직임을 넣기보다 정지 그림으로 전달하기 어려운 원리 하나에 배치하면 서로의 역할이 겹치지 않는다.

아나토미 1.0은 클로드에게 예쁜 그림뿐 아니라 설명할 수 있는 장치를 만들게 하는 외부 개발자 도구다. 기계의 동작을 웹에서 보여 주는 제작 기준과 검사 도구를 묶었다는 점이 핵심이다. 교육 자료로 완성하는 마지막 단계에는 사람이 원리와 수치를 대조하는 일이 남는다.
