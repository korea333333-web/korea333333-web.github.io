클로드, 유료 앱에서 실행마다 묻던 승인을 줄인다…다음 주 확대

앤트로픽이 유료 클로드 앱에서 작업을 시작할 때 적용하는 승인 방식을 바꾼다. 2026년 10월 22일 공식 안내에 따르면, 다음 주부터 Pro·Max·Team 요금제의 대부분 앱에서 새 작업이 자동 모드로 시작된다. 사용자가 실행마다 허락하는 대신 별도 AI 검사가 위험한 행동을 걸러내는 방식이다. 정확한 적용 요일은 공개하지 않았다. 공식 업데이트

이 변화는 긴 일을 맡길 때 더 잘 드러난다. 예를 들어 자료를 정리하고 파일을 고치는 동안 매 단계에 답하느라 화면을 지켜봤다면, 앞으로는 반복적인 승인 요청이 줄어들 수 있다. 대신 사용자는 어떤 작업을 맡겼고 어떤 변경까지 허용했는지 처음에 더 분명하게 알려주는 편이 좋다.

새 기능의 탄생보다 기본 설정의 확대

자동 모드는 이미 코딩용 도구인 Claude Code에 있었다. 8월 7일 안내는 8월 14일부터 유료 세 요금제에 기본 적용한다고 예고했다. 이번 소식은 그 글에 추가된 10월 22일 갱신 내용이다. Enterprise 조직은 기본 적용 전에 관리자에게 이메일로 알린다. 적용 날짜와 대상

기본 설정은 사용자가 다른 선택을 하지 않았을 때 먼저 적용되는 값이다. 그래서 이번 변화는 기능 메뉴가 하나 늘어나는 일보다 영향이 크다. 평소 쓰던 앱에서 새 일을 시작했는데 확인 창이 줄었다면, 모델이 갑자기 모든 권한을 얻은 것인지보다 현재 승인 모드부터 살펴볼 이유가 생긴다.

일하는 AI와 실행을 검사하는 AI를 나눈다

Claude Code의 권한 안내를 보면 차이를 구체적으로 이해할 수 있다. 수동 모드에서는 파일 수정, 명령 실행, 인터넷 접근 등 여러 행동 앞에서 사용자의 답을 기다린다. 자동 모드에서는 별도의 분류기가 해당 행동을 검토한다. 여기서 분류기는 명령과 요청 내용을 읽고 허용 여부를 판단하는 또 다른 AI다.

자동 검사와 검사 생략은 다르다. 공식 문서에는 승인 검사를 건너뛰는 별도 모드도 있지만, 자동 모드는 검토자를 사람에서 AI로 바꾸는 쪽이다. 요청보다 큰 변경, 낯선 외부 시스템 접근, 읽어 온 악성 문구의 지시를 따르는 행동 등을 차단 대상으로 살핀다.

검사 범위는 제품과 설정에 따라 달라진다. Claude Code에서는 읽기와 일부 작업 폴더 수정처럼 별도 분류기 검사를 생략하는 행동도 있다. 사용자가 명시적으로 확인하도록 정한 규칙은 자동 모드에서도 승인 요청을 유지한다. 따라서 ‘모든 클릭을 빠짐없이 같은 AI가 검사한다’보다 ‘제품의 권한 규칙과 자동 검사가 함께 실행을 정한다’가 정확하다.

89%는 어떤 시험에서 나온 수치인가

앤트로픽은 기존 Claude Code 시험에서 사람의 검토가 위험 명령의 13.6%, 자동 모드가 89%를 차단했다고 밝혔다. 유료 전문 시험 참여자 1,053명에게 코딩 작업을 맡기고, 도중에 위험한 명령 하나를 승인 요청에 끼워 넣은 실험이다. 승인해도 실제 위험 명령이 실행되지는 않았다. 회사가 제시한 제한된 시험 결과다.

이 실험은 승인 버튼을 누르는 사람이 실제로 명령을 읽고 판단했는지를 보여준다. 반복 확인을 모두 사람에게 맡겨도 실제 검토가 이뤄지지 않으면 보호 효과가 약해진다. 자동 검사는 그 반복 업무를 맡겠다는 접근이다. 새 앱의 실제 사용 결과는 적용 이후 따로 확인할 부분이다.

공격을 일부러 시키면 다른 약점도 드러난다

앤트로픽 연구진은 10월 22일 별도 자동 검사 공격 시험도 공개했다. 여기서는 AI에게 정상 업무만 시키지 않았다. 검사 장치를 속이거나 여러 작업에 행동을 나눠 위험한 일을 끝내도록 공격 목표를 줬다. 시험자가 일부러 약점을 찾는 이런 과정을 보안 공격 시험, 또는 레드팀 시험이라고 부른다.

그 연구는 2026년 9월 당시 검사 장치의 모습을 다룬다. 여러 작업의 맥락을 한꺼번에 보지 못하거나, 기록을 줄이는 과정에서 앞선 위험 단서가 사라지는 문제가 조사됐다. 연구진은 도구의 검사 범위를 늘리고 기록을 더 잘 보여주는 개선안을 시험했다. 비용을 크게 늘리지 않으면서 이런 공격을 안정적으로 막는 일은 여전히 과제로 남았다.

앞의 89%와 이 연구의 공격 결과를 한 그래프에 섞으면 안 된다. 하나는 사람이 승인 창에서 놓친 명령과 비교한 시험이고, 다른 하나는 방어 장치를 집중적으로 속이도록 시킨 시험이다. 공격자에게 준 정보와 실행 환경도 다르다. 같은 ‘안전’이라는 말 아래에 있어도 측정한 질문은 각각이다.

업무에서 남겨둘 사람의 확인 지점

개발자와 관리자는 자동 모드를 켜면서도 특정 행동은 사람이 확인하도록 정할 수 있다. 공식 설정 문서는 프로그램 변경을 외부 저장소에 올리기 전에 승인을 요구하는 규칙 등을 설명한다. 저장소는 코드와 수정 기록을 보관하는 공동 폴더다. 사용자가 맡긴 수정과 외부 공개를 구별할 때 유용한 장치다.

문서가 구분하는 세 가지 경계도 중요하다. 어떤 행동은 승인 창을 띄우고, 어떤 행동은 아예 실행하지 못하게 막으며, 대화 속 지시는 이번 작업의 범위를 설명한다. 대화 기록이 줄어드는 과정에서 지시가 빠질 수 있으므로, 반드시 지켜야 하는 제한은 제품의 권한 설정으로 남기는 편이 더 강하다.

다음은 이를 일상 작업으로 옮긴 가상의 예다. ‘문서를 완성해 줘’보다 ‘이 폴더의 자료로 초안을 만들고, 고객에게 보내는 단계는 내가 확인한 뒤 진행해 줘’라고 요청하면 사람과 AI의 역할이 분명해진다. 실제 발송을 막는 기능이 필요한 업무라면 지시 문장과 별도로 사용하는 앱의 권한 제한도 함께 적용한다.

Claude Code를 쓰는 사람은 명령창에서 Shift+Tab으로 승인 모드를 바꿀 수 있다. 데스크톱 앱의 Code 탭에는 입력창 아래 모드 선택기가 있다. 이 조작법은 코딩 도구 기준이다. 일반 대화·Cowork 등 다른 기능의 메뉴와 그대로 같다고 가정하지 말고 해당 화면의 안내를 따른다. 화면별 모드 선택 안내

편리함을 늘리되 맡긴 범위는 분명하게

이번 일반 앱 확대 안내에는 추가 요금이나 사용 한도 변경이 따로 적혀 있지 않다. 무료 요금제도 대상에 포함되지 않았다. 유료 사용자는 다음 주 적용 안내를 기준으로 자신의 새 작업에 어떤 모드가 선택됐는지 확인하면 된다.

클로드의 변화는 사람이 누르는 승인 횟수를 줄이고 반복 검사를 별도 AI에 맡기는 것이다. 중요한 발송이나 실제 서비스 변경에는 여전히 사람의 판단이 필요하다. 반복 작업은 이어가게 하되, 되돌리기 어려운 행동은 사람이 확인할 지점을 남기는 것이 이번 기능을 이해하는 핵심이다.

이 글은 공식 문서와 공개 연구를 대조한 해설이다. 새 앱 자동 모드를 직접 실행한 후기는 아니다. 그래프와 시간표는 확인한 사실로 직접 만들었으며 공식 제품 화면·시연 영상은 재게시하지 않았다.
