Qwen3.8-Max 정식 공개, 2.4조 매개변수보다 중요한 것

Alibaba의 Qwen 팀이 8월 3일 Qwen3.8-Max를 정식 공개했다. 2.4조 개의 전체 매개변수와 토큰마다 활성화되는 950억 개의 매개변수, 코딩·사무·멀티모달 에이전트용 기능, 상세 벤치마크 표가 처음 한꺼번에 나왔다. 그러나 가장 관심을 끄는 ‘오픈웨이트’는 아직 도착하지 않았다. 팀은 가중치를 다음 주 Hugging Face와 ModelScope에 공개하겠다고 예고했을 뿐이다. 지금 확인된 제품과 앞으로 지켜봐야 할 약속을 나누는 것이 이 발표를 제대로 읽는 첫 단계다.

Qwen의 공식 릴리스 글은 Qwen3.8-Max를 Qwen 계열에서 지금까지 가장 강력한 모델이라고 소개한다. 7월 19일의 Preview 발표가 모델 규모와 ‘곧 오픈웨이트’라는 방향만 제시했다면, 이번 글은 활성 매개변수, 평가 설정, 긴 작업 사례, API 사용법을 공개했다. 모델은 현재 Qwen의 클라우드 API와 코딩·업무 제품에서 이용할 수 있다.

2.4조라는 숫자는 모델이 매번 2.4조 개를 모두 계산한다는 뜻이 아니다. 희소 Mixture-of-Experts 구조가 입력에 따라 일부 전문가만 선택하며 토큰당 활성 매개변수는 950억 개라고 회사는 밝혔다. 전체 규모는 저장·배포 부담을, 활성 규모는 추론 계산량을 이해하는 출발점이지만 실제 속도와 비용은 정밀도, 메모리 대역폭, 병렬화와 소프트웨어 최적화에 따라 달라진다.

프리뷰에서 정식 릴리스로 바뀐 것

7월 프리뷰에서 가장 큰 빈칸은 근거였다. MarkTechPost의 당시 점검은 벤치마크 표, 모델 카드, 라이선스, 활성 매개변수가 모두 공개되지 않았다고 지적했다. SCMP도 Alibaba가 Fable 5 다음이라고 주장했다는 수준에서 보도했다. 이번 정식 글은 적어도 회사가 어떤 평가를 근거로 그 말을 했는지 살펴볼 수 있게 했다.

Qwen이 강조하는 능력은 단발성 질의응답보다 긴 작업이다. 공개 글에는 터미널 작업, 연구 논문 재현, 칩 설계 반복, 웹·문서·영상 처리처럼 모델이 도구를 여러 번 부르고 결과를 다시 검사하는 사례가 담겼다. 이 방향은 코딩 모델을 ‘코드 자동완성’이 아니라 프로젝트를 오래 운영하는 에이전트로 바꾸려는 업계 흐름과 맞닿아 있다.

멀티모달도 입력을 한 번 읽는 데 그치지 않는다. Qwen은 이미지와 영상을 에이전트의 메모리·도구 사용·결과 확인에 연결하는 플러그인 계층을 소개했다. 화면을 보고 코드를 고치거나 문서를 읽고 표를 다시 만드는 일처럼 시각 입력이 작업 중간에 반복해서 들어오는 구조다.

API 호환성은 개발자가 체감할 변화다. 공식 글은 OpenAI와 Anthropic 형식의 프로토콜, 여러 단계의 `reasoning_effort`, 텍스트·이미지·영상 입력을 설명한다. 기존 도구를 크게 바꾸지 않고 모델을 비교할 수 있다는 뜻이지만, 호환되는 요청 형식이 같은 행동과 품질을 보장하지는 않는다. 도구 호출 오류와 긴 대화의 상태 유지 능력은 자체 평가가 필요하다.

벤치마크는 ‘전 영역 1등’이 아니라 성향을 보여 준다

공식 표에서 Qwen3.8-Max는 Terminal Bench 2.1에서 86.6점을 기록해 Qwen3.7-Max의 74.5를 크게 웃돌고, Fable 5의 84.6보다 높았다. PaperBench도 93.0으로 Fable 5의 88.8을 넘었다. IFBench는 82.8 대 63.5, Parametric CAD Bench는 91.5 대 87.5, OmniDocBench 1.5는 92.1 대 89.5였다.

반대쪽 숫자도 함께 봐야 한다. SWE-bench Pro에서는 67.7로 Fable 5의 80.0에 못 미쳤고, FrontierSWE는 73.5 대 88.8이었다. 일반 지식·추론 성격의 HLE는 43.6 대 53.3, Toolathlon Verified는 72.5 대 77.9였다. 한두 개의 승리만 뽑으면 모델의 실제 강약점이 사라진다.

평가 조건도 중요하다. Qwen은 Terminal Bench에 Claude Code 하네스와 5시간 제한을 썼고, SWE-bench Pro에는 별도의 수정된 벤치마크와 256K 컨텍스트를 사용했다고 각주에 밝혔다. 경쟁 모델은 공개된 최고 점수를 가져온 경우도 있다. 동일한 서버와 하네스에서 모든 모델을 다시 돌린 완전한 독립 대조시험과는 다르다.

따라서 지금의 정확한 결론은 Qwen3.8-Max가 회사 평가에서 이전 세대보다 폭넓게 개선됐고, 특히 문서·시각 작업과 일부 긴 에이전트 과제에서 강한 프로필을 보였다는 것이다. ‘Fable 5를 전반적으로 이겼다’거나 ‘세계 2위가 확정됐다’는 문장은 표 자체가 보여 주는 혼합된 결과와 맞지 않는다.

100만 토큰급 컨텍스트도 기억력과 같은 말은 아니다. 긴 문서를 한 번에 넣을 수 있어도 중간에 묻힌 세부 사실을 안정적으로 찾고 서로 모순되는 부분을 처리하는 능력은 별개다. 최대 입력 길이에서의 지연과 비용, 도구 호출을 반복한 뒤 초반 지시를 유지하는지까지 시험해야 실제 업무 한계를 알 수 있다.

긴 작업 사례는 흥미롭지만 성공한 시연의 선택 편향을 피하기 어렵다. 16일 동안 코드를 만들거나 수백 번 설계를 고친 사례가 있다면 같은 조건에서 실패한 시도와 사람이 개입한 지점도 알아야 한다. 재현 가능한 저장소와 실행 로그, 중단 기준이 공개돼야 ‘오래 실행됐다’와 ‘오래 자율적으로 일했다’를 구분할 수 있다.

멀티모달 평가에서는 자동 심판 모델의 편향도 살펴야 한다. 렌더링된 웹페이지나 문서를 다른 대형 모델이 채점하면 심판이 선호하는 문체와 레이아웃이 높은 점수로 이어질 수 있다. 사람이 실제로 편집하기 쉬운지, 숫자가 맞는지, 접근성이 지켜졌는지는 별도의 평가 항목이다.

오픈웨이트 약속이 중요한 이유

Qwen-Max급 모델의 가중치를 처음 공개하겠다는 예고는 제품 발표보다 더 큰 전략 변화일 수 있다. 지금까지 대형 Max 계열은 주로 클라우드로 제공됐지만 체크포인트가 실제로 열리면 연구자는 내부 구조를 검사하고, 별도 환경에서 평가하고, 필요한 경우 자체 인프라에 배포할 수 있다. 미국 폐쇄형 프런티어 모델과 경쟁하는 중국 진영의 선택지가 넓어진다.

그러나 ‘오픈웨이트’는 ‘완전한 오픈소스’와 같은 말이 아니다. 훈련 데이터, 학습 코드, 후처리 절차가 공개되지 않을 수 있고 라이선스가 특정 국가·용도·규모의 사용을 제한할 수도 있다. 저장소가 열리기 전에는 상업적 재배포 가능 여부나 모델을 수정한 파생물의 조건을 단정할 수 없다.

하드웨어 장벽도 현실적이다. 2.4조 매개변수는 낮은 정밀도로 압축해도 막대한 저장 공간과 여러 대의 고성능 가속기가 필요하다. 활성 매개변수가 950억이라는 사실은 추론량을 줄이지만 모든 전문가 가중치를 메모리에 배치해야 하는 문제를 없애지 않는다. 개인용 GPU에서 Max 전체를 바로 돌릴 수 있다는 기대는 현실적이지 않다.

같이 예고된 Qwen3.8-27B가 그래서 중요하다. 규모가 훨씬 작은 모델이 Max의 학습 개선을 얼마나 이어받는지에 따라 실제 개발자 채택이 달라질 수 있다. 많은 조직에는 2.4조 모델의 최고 점수보다 한두 대의 서버에서 안정적으로 돌아가고 수정할 수 있는 27B 모델이 더 유용하다.

이번 선택은 중국 AI 기업의 경쟁 방식도 보여 준다. 미국의 선두 연구소가 대형 모델을 API로만 제공하는 동안 중국 팀들은 가중치 공개로 개발자 생태계와 파생 모델을 빠르게 넓혀 왔다. Max급까지 이 전략이 확대되면 연구자는 더 큰 모델의 라우팅과 압축을 직접 분석할 수 있지만, 서비스 역량과 자본이 있는 소수 조직만 전체 모델을 운영할 가능성도 크다.

공개 가중치는 수출 규제와 하드웨어 제약을 없애지 않는다. 체크포인트를 내려받을 수 있어도 학습과 추론에 필요한 가속기, 네트워크, 전력과 최적화 소프트웨어가 병목이 된다. 모델 공개 경쟁과 반도체 공급 경쟁이 동시에 진행되는 이유이며, 순수한 매개변수 수만으로 국가 간 격차를 재단하기 어려운 지점이다.

다음 주에 확인할 것은 파일의 존재만이 아니다. 라이선스 전문, 체크포인트 크기와 형식, 양자화 지원, 모델 카드, 안전 평가, 공식 추론 코드, 제3자 재현 점수가 함께 나오는지를 봐야 ‘오픈웨이트 발표’가 실제 사용 가능한 공개로 바뀐다.

한국 개발자와 기업이 지금 할 일

API를 시험할 팀은 자사 작업을 작은 평가 세트로 먼저 고정하는 편이 좋다. 한국어 문서 이해, 실제 코드 저장소 수정, 함수 호출 성공률, 100만 토큰에 가까운 긴 입력에서의 정보 회수, 이미지·영상 처리 결과를 따로 측정해야 한다. 공식 벤치마크에서 강한 영역이 한국어 업무에서도 같은 순서로 나타난다는 보장은 없다.

가격만 비교할 때도 토큰 단가 외의 비용을 넣어야 한다. 긴 사고 모드는 더 많은 출력과 지연을 만들 수 있고, 도구 호출이 실패하면 재시도 비용이 늘어난다. 같은 업무를 끝내는 데 필요한 총 토큰, 완료 시간, 사람이 수정한 비율을 기록해야 폐쇄형 모델과 오픈웨이트 배포를 공정하게 비교할 수 있다.

가중치를 기다리는 팀은 인프라 견적을 서두를 필요가 없다. 공식 파일의 정밀도와 전문가 배치 방식, 텐서 병렬 지원, 최소 메모리, 라이선스를 본 뒤 결정해야 한다. 27B 버전의 품질이 충분하다면 Max 자체 호스팅보다 작은 모델과 필요할 때만 쓰는 Max API를 조합하는 편이 경제적일 수 있다.

보안 부서는 모델 출신 국가만으로 결론을 내리기보다 배포 방식별 데이터 흐름을 그려야 한다. 클라우드 API에 보내는 프롬프트와 파일의 저장 정책, 자체 호스팅 가중치의 공급망, 업데이트 서명, 도구 실행 권한은 서로 다른 위험이다. 오픈웨이트는 검사 가능성을 높이지만 자동으로 안전하거나 규정 준수를 보장하지 않는다.

한국어 품질은 별도의 문턱이다. 중국어와 영어 중심의 공개 점수가 한국 법률·제조·공공 문서에서의 용어 일관성, 높임말, 표 해석, 날짜·통화 표기를 대신하지 못한다. 실제 계약서와 매뉴얼을 익명화한 평가 세트를 만들고, 한국어 답변의 사실 오류와 도구 인수 전달 오류를 분리해 측정해야 한다.

모델을 자체 호스팅해도 운영 책임은 남는다. 안전 필터, 접근 권한, 취약한 도구 호출, 프롬프트 주입, 저작권 요청 처리, 모델 업데이트와 회귀 시험을 조직이 직접 맡아야 한다. API 공급자가 제공하던 통제 기능을 비용표에서 빼면 오픈웨이트의 경제성이 실제보다 좋아 보일 수 있다.

앞으로 확인할 지표는 세 갈래다. 첫째, 약속한 날짜에 Max와 27B 가중치가 실제로 올라오는지, 둘째, 독립 평가에서 공식 표의 강점과 약점이 재현되는지, 셋째, Qwen Cloud와 자체 호스팅의 지연·비용·안정성이 어떤 차이를 보이는지다. 체크포인트 수정이나 라이선스 변경도 버전별로 추적해야 한다.

독립 평가 기관과 커뮤니티가 체크포인트를 받은 뒤에는 초기 점수의 변동도 자연스럽게 받아들여야 한다. 다른 양자화, 추론 엔진, 프롬프트 형식에서 성능이 달라질 수 있고 공식 하네스의 수정 사항이 발견될 수도 있다. 중요한 것은 첫날 순위가 아니라 Alibaba가 재현 절차와 오류 제보에 응답하고, 모델 카드와 체크포인트를 버전으로 관리하며, 수정 이유를 공개하는지다.

필자의 결론은 2.4조라는 크기가 이번 발표의 핵심이 아니라는 것이다. Qwen3.8-Max는 프리뷰의 빈칸을 상당 부분 채워 비교 가능한 제품이 됐지만, 검증 가능한 공개 모델이 되는 마지막 선은 아직 넘지 않았다. 다음 주 저장소에 무엇이, 어떤 조건으로, 얼마나 재현 가능하게 올라오느냐가 중국 프런티어 AI의 개방 전략을 판단할 진짜 뉴스다.
