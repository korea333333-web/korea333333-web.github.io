Meta, Muse Spark 1.3 출시…긴 작업과 코딩 효율을 다듬었다

Meta가 9월 2일 Muse Spark 1.3을 Muse Code와 Meta Model API에 출시했다. 새 모델은 한 대화 안에서 여러 일을 오래 이어 가고, 복잡한 지시를 덜 놓치며, 코딩 과정에서 불필요한 도구 호출과 토큰 사용을 줄이는 데 초점을 맞췄다.

Meta 공식 발표에서 가장 먼저 강조한 변화는 ‘더 큰 모델’이 아니라 작업 지속력이다. 열려 있는 목표를 받으면 여러 도구로 흩어진 자료를 모으고, 계획의 빈칸을 고치고, 이미 배운 내용을 기록해 최종 결과물까지 이어 가도록 훈련했다는 설명이다.

한 채팅에서 사용자가 과거 요청을 바꾸거나 중간에 새 일을 끼워 넣을 때 어느 작업에 해당하는지 더 정확히 연결하는 기능도 강조됐다. 애매한 요청에는 확인 질문을 하고, 막히면 도움을 청하며, 되돌리기 어려운 행동 전에는 확인하도록 훈련했다는 점이 이전보다 실무적인 변화다.

이 설명은 모델이 절대로 엉뚱한 일을 하지 않는다는 보증이 아니다. ‘확인을 잘한다’는 성향과 실제 제품의 권한 통제는 별개다. 파일 삭제, 외부 메시지 전송, 결제, 배포처럼 결과가 남는 행동은 모델 판단과 무관하게 도구 자체에서 승인 단계를 두어야 한다.

20%와 25%는 회사 내부 비교에서 나온 수치다

코딩에서는 Muse Spark 1.2보다 필요 없는 왕복을 줄이고 답변을 덜 장황하게 만들었다고 Meta는 설명한다. Meta 엔지니어들의 비교에서 1.3은 도구 호출을 약 20%, 토큰을 약 25% 덜 사용하면서 더 빠르고 효율적으로 작동했다.

이 숫자는 모든 저장소와 모든 프롬프트에서 비용이 정확히 그만큼 줄어든다는 뜻이 아니다. 표본 수, 저장소 구성, 실패 뒤 재시도 포함 여부와 분포가 공식 짧은 발표문에는 나오지 않는다. Meta 직원의 비교 결과이므로 각 팀은 자신의 코드베이스에서 끝까지 성공한 작업당 비용으로 다시 재야 한다.

Artificial Analysis가 확인한 일반 API 가격은 입력 100만 토큰당 1.25달러, 출력 4.25달러다. 개발 데이터를 Meta의 모델 개선에 쓰도록 허용하는 Contributor 경로는 입력 0.10달러, 출력 0.20달러로 훨씬 싸다. 비공개 코드나 고객 자료에는 가격보다 최신 데이터 이용 조건을 먼저 확인해야 한다.

Meta가 공개한 시연은 ‘대화 답변’보다 산출물 사이의 연결을 보여 준다. 항공우주 예시는 계산 유체 역학 보고서와 STEP 설계 파일을 함께 만들고, 오디오 예시는 DOCX의 타임코드와 여러 스템을 읽어 최종 WAV를 편집한다. 지방정부 업무에서는 카운티 정책을 설명하는 발표자료를 만들거나 주민 의견 스프레드시트를 분석해 서로 다른 두 PDF 보고서로 나눈다. 다만 각 영상에는 ‘실제 제품이 아닌 AI 에이전트 프로토타입’이라는 표시가 붙어 있다. 시연이 성공했다는 사실을 Muse Code의 모든 설치 환경이나 파일 형식 호환성 보장으로 확대하면 안 된다.

이런 복합 작업을 직접 시험할 때는 원본 파일과 도구 버전을 고정하고, 최종 산출물뿐 아니라 중간 판단 기록도 보관하는 편이 좋다. 같은 업무를 여러 번 실행해 파일 손상, 빠진 출처, 도구 호출 실패와 사람이 수정한 시간을 따로 세면, 공개 시연을 자기 환경의 생산성 수치로 바꾸어 검증할 수 있다.

업무형 점수의 구성도 함께 봐야 한다. GDPVal-AA v2는 미국 9개 산업, 44개 직종에서 모은 현실형 과제 220개를 셸과 웹을 쓸 수 있는 환경에서 수행하게 한다. LLM 심사기는 익명화한 산출물을 쌍대 비교하고, 인간 기준점을 1,000으로 둔 Elo 점수로 환산한다. JobBench는 35개 사무직의 65개 과제를 직무별 루브릭으로 채점한다. 두 시험은 짧은 정답률보다 문서·표·코드 같은 완성 결과물을 보지만, 회사별 승인 절차나 사내 도구 권한까지 재현하는 것은 아니다.

조사와 자동화 표의 숫자도 서로 다른 능력을 잰다. DeepSearchQA는 900개의 목록형 질문에 동일한 검색 백엔드와 실행 틀을 제공한 뒤 정밀도와 재현율을 합친 F1으로 채점한다. AutomationBench는 600개의 모의 사무 워크플로에서 작업 뒤 시스템의 최종 상태를 결정론적 조건으로 검사하고, 한 번의 실행 성공률인 pass@1을 쓴다. 따라서 전자는 필요한 항목을 빠뜨리지 않았는지, 후자는 실제 상태 변경을 끝냈는지에 더 가깝다. 둘 중 어느 점수도 그럴듯한 설명문 자체의 품질을 직접 보증하지 않는다.

초장문 결과에는 별도의 주의가 필요하다. MRCR v2는 25만6천~51만2천 토큰 구간과 51만2천~100만 토큰 구간에서 각각 100개 예시를 사용하고, 여덟 개의 숨은 단서를 찾아내는 과제를 도구 없이 규칙 기반으로 채점한다. 이는 백만 토큰 안에서 특정 정보를 회수할 수 있는지를 보여 주지만, 며칠간 이어지는 에이전트가 모든 제약을 기억하거나 중간 산출물을 올바르게 갱신한다는 뜻은 아니다.

코딩 표의 DeepSWE는 91개 저장소에서 고른 113개 과제로 TypeScript·Go·Python·JavaScript·Rust를 다루며, 사람이 작성한 기능·회귀 테스트로 결과를 확인한다. Muse의 값은 Meta가 자체 실행한 결과라 공개 리더보드의 동일 조건 재현치와 구분해야 한다. 결국 20% 호출 감소와 25% 토큰 감소를 실제 절감으로 인정하려면, 같은 업무와 도구 권한으로 완료율·재시도·벽시계 시간·모델 외부 비용까지 나란히 기록해야 한다.

예를 들어 모델이 도구를 열 번 쓰던 일을 여덟 번에 끝내도 잘못된 파일을 고쳐 사람이 되돌리면 전체 비용은 늘 수 있다. 반대로 호출 수가 많더라도 검증과 테스트를 충실히 해 한 번에 통과한다면 실무 비용은 낮아진다. 단위 작업 성공률, 실행 시간, 토큰, 사람의 수정 시간을 함께 기록해야 한다.

오늘 쓸 수 있는 것과 ‘곧’ 나올 것을 나눠 봐야 한다

Meta는 발표 당일부터 Muse Code와 Meta Model API 배포를 시작했다고 밝혔다. 다만 공식 발표에는 국가 목록이 없어 한국 계정에서 직접 이용 가능한지는 등록 화면과 계약에서 별도 확인해야 한다. 이전에 제공하던 추론 모드는 사용할 수 있지만, 가장 많은 계산을 쓰는 max reasoning은 추가 안전성 시험을 마친 뒤 제공될 예정이다. 정확한 날짜는 발표문에 없다.

오픈 가중치도 아직 배포된 것이 아니다. Meta는 앞으로 Muse Spark 오픈 가중치를 내놓을 계획이라고 했지만 날짜, 라이선스, 모델 크기와 배포 범위를 밝히지 않았다. 따라서 현재의 1.3을 ‘오픈소스 모델’이라고 소개해서는 안 된다.

Muse Code 공식 설치 명령은 macOS와 Linux를 대상으로 제시됐다. Windows의 네이티브 지원 방식은 이번 발표문에서 안내하지 않았다. API나 별도 환경을 통해 접근하는 방법과 로컬 명령줄 도구의 지원 운영체제를 같은 것으로 보면 안 된다.

이번 발표의 제품 범위는 Muse Code와 Meta Model API다. Meta AI 소비자 앱, WhatsApp, Instagram과 Facebook에 1.3이 즉시 적용됐다고 볼 근거는 발표문에 없다. 개인용 서비스에서 보이는 이름이 같더라도 선택 가능한 추론 수준과 도구 권한은 개발자 제품과 다를 수 있다.

한국 개발자는 계정 지역과 결제 통화, API 할당량을 등록 화면에서 먼저 확인해야 한다. 명령줄 설치 안내가 macOS와 Linux만 제시된 만큼 Windows에서는 공식 지원 여부를 확인하고, WSL이나 원격 Linux를 쓴다면 파일 경로와 자격정보가 어느 환경에 남는지도 점검해야 한다.

작은 도입 시험은 같은 열 개 안팎의 실제 작업을 1.2와 1.3에서 여러 번 실행하는 것으로 충분하다. 완료율, 첫 응답과 전체 시간, 도구 호출, 입력·출력 토큰, 사람이 되돌린 변경을 한 표에 기록하면 회사 평균과 자기 팀의 효과를 구분할 수 있다. Contributor 경로는 비민감 공개 코드에 한정해 일반 경로와 데이터 조건까지 함께 비교하는 편이 안전하다.

벤치마크 표는 서로 다른 측정값을 한곳에 모았다

Meta의 4쪽짜리 평가 방법 보고서는 전문 업무, 컴퓨터 사용, 웹 조사와 자동화, 소프트웨어 공학, 긴 문맥 검색을 평가했다고 설명한다. 표의 Muse Spark 1.3·Claude Opus 5·GPT-5.6 Sol은 max, Muse Spark 1.2는 xhigh로 비교했다. 1.3의 max는 출시일에 일반 제공되지 않은 설정이다.

주의할 대목은 점수 출처다. 보고서는 자체 실행값, 공식 순위표, 다른 모델 회사가 발표한 값 가운데 비교 가능한 가장 높은 값을 사용한다고 적었다. 경쟁 모델 실행은 최선의 노력이지만 각 회사 모델에 맞게 완전히 최적화됐다고 보장하지 않는다. 하나의 공통 실험실에서 모든 모델을 똑같이 돌린 순위표와는 다르다.

일부 과제는 버전도 다르다. OSWorld 2.0에서 1.3은 08.08 버전, 1.2는 06.24 버전을 사용했다. Meta의 IF Index는 여러 내부 평가를 합친 지표라 단일 공개 과제 수가 없다. 이전 모델 대비 추세를 볼 수는 있어도 작은 점수 차이로 승자를 단정하기 어렵다.

DeepSWE 항목에서 Meta는 1.3 max를 자체 실행해 75.4점을 얻고 경쟁 모델 값은 공개 순위표에서 가져왔다. 현재 공개 순위표 자체에는 1.3 결과가 없어 독립 재현값이라고 부를 수 없다. 동일 저장소, 테스트, 추론 수준과 권한에서 여러 모델을 직접 돌리는 작은 검증이 더 값지다.

안전성 개선은 권한 설계를 대신하지 않는다

Meta는 1.3이 적대적 입력과 프롬프트 주입에 더 강하고, 되돌릴 수 없는 행동을 더 잘 구분한다고 밝혔다. 동시에 가장 강한 추론 모드는 추가 안전 시험 때문에 늦춰 두었다. 그러나 1.3 발표에는 정량 안전 점수나 별도 안전 보고서가 없어 개선 폭을 외부에서 확인하기 어렵다.

4월의 첫 Muse Spark 발표에는 당시 모델의 평가 인식 문제가 기록돼 있지만 버전과 개념이 달라 이를 1.3의 자기 인식 주장에 연결할 수는 없다. 현재 확인 가능한 것은 Meta의 개선 설명과 max 출시 전 추가 시험 계획이다.

실무에서는 첫 시험을 읽기 전용 저장소나 임시 브랜치에서 시작한다. 네트워크, 비밀키, 운영 데이터베이스 접근은 최소화하고 커밋·배포·삭제·메시지 전송 전에 사람 승인을 둔다. 모델이 스스로 확인 질문을 하도록 훈련됐더라도 승인 규칙은 시스템이 강제해야 한다.

평가 항목도 단순 코드 생성에서 끝내지 않는다. 요구사항 누락, 다른 작업으로의 문맥 섞임, 테스트 통과율, 잘못된 성공 보고, 중단 뒤 복구, 변경 설명의 정확성을 본다. 1.3이 내세운 장점이 바로 이런 긴 흐름이기 때문이다.

아직 모르는 것

공식 짧은 발표만으로는 20%·25% 비교의 표본과 분포, max reasoning 출시일, 오픈 가중치의 날짜·라이선스, 모든 지역의 API 가격과 할당량을 확정할 수 없다.

Meta가 말하는 ‘개인 초지능’은 장기 목표다. 이번에 사용자가 당장 평가할 수 있는 제품 변화는 훨씬 구체적이다. 한 대화에서 여러 작업을 덜 섞는지, 긴 지시를 끝까지 지키는지, 불필요한 호출과 설명을 줄이면서도 결과를 검증하는지가 핵심이다.

특히 공개 가중치와 max reasoning이 실제로 풀릴 때는 오늘의 시험 결과를 그대로 재사용하지 말고, 같은 과제와 권한으로 다시 비교해야 한다. 접근 경로가 바뀌면 성능뿐 아니라 비용·보안·감사 가능성도 함께 달라질 수 있기 때문이다.

Muse Spark 1.3은 긴 일을 맡겼을 때 덜 헤매고 덜 낭비하도록 모델 성능과 운영 사용성을 함께 다듬은 점진적 업데이트다. 회사가 제시한 효율 수치는 매력적이지만, 도입 여부는 자신의 저장소에서 성공 작업당 비용과 사람의 수정 시간까지 재본 뒤 결정해야 한다.
