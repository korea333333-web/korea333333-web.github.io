미니맥스, 사진·영상을 읽고 코딩하는 AI 파일 공개

중국 AI 기업 미니맥스가 사진과 영상을 읽고 코드를 작성하는 ‘MiniMax M3.1 Flash’의 모델 파일을 공개했다. 10월 19일에는 API와 앱에서 제공한다고 발표하면서 파일 공개는 나중으로 예고했다. 이후 10월 23일 Hugging Face에 실제 파일이 올라왔다. 서비스를 빌려 쓰는 방법에 더해, 장비를 갖춘 개발자가 직접 운영할 선택지가 생겼다. 10월 19일 발표 · 공개 파일

이 모델은 글·사진·영상을 입력받고 글로 답한다. 사진 속 화면을 설명하거나 영상을 참고해 분석하고, 필요한 코드를 만드는 종류다. 영상 파일을 넣는다고 새 영상을 직접 생성하는 모델은 아니다. 미니맥스의 영상 생성 제품 H3와도 역할이 다르다. 공식 모델 목록

예를 들어 웹페이지의 문제 화면과 관련 코드를 함께 주고 “모바일에서 이 버튼이 가려지는 원인을 찾아 달라”고 요청하는 상황을 생각할 수 있다. 화면에 나타난 현상과 코드에 적힌 원인을 함께 살피는 작업이다. 실제 파일을 고치고 브라우저로 확인하려면 모델 외에 코드 편집·실행 도구와 그 도구를 쓸 권한도 필요하다.

공식 사례는 결과뿐 아니라 작업 환경까지 봐야 한다

회사는 MiniMax Code의 사례로 느려진 고객 문의 관리 화면을 분석하고 고친 작업을 소개한다. 같은 8,000개 기록으로 세 번 측정한 성능 비교와 수정된 화면도 제시한다. 이는 회사가 공개한 특정 사례다. 내 서비스에 연결하면 같은 개선 폭이 나온다는 보장은 아니며, 이 기사는 해당 코드를 내려받아 재현하지 않았다. 공식 사례와 화면

이 사례에서 눈여겨볼 부분은 ‘코드를 써 준다’보다 작업의 연결이다. 느린 화면을 보고, 원인을 좁히고, 코드를 바꾼 뒤 실제 조작으로 다시 확인하는 순서다. 사용자는 결과 설명만 받아서는 어느 단계가 끝났는지 알기 어렵다. 수정 파일과 시험 기록이 함께 남아야 일이 제대로 끝났는지 판단할 수 있다.

모델을 내 서버에 올려도 이 순서가 자동으로 완성되지는 않는다. 모델이 글로 제안한 명령을 실제 도구가 실행하도록 연결해야 한다. 그 연결을 에이전트라고 부르는 경우가 많다. 여기서 에이전트는 별도의 사람이 아니라, AI가 도구를 선택하고 결과를 받아 다음 행동을 정하는 프로그램 구성이다. 무엇을 실행할 수 있게 허용할지는 운영자가 정한다.

큰 모델의 일부만 계산에 쓰는 구조

M3.1 Flash의 전체 규모는 약 4,280억 개이며, 답변을 한 조각 만들 때 약 230억 개가 계산에 참여한다. 이 개수는 학습된 숫자인 파라미터를 센 것이다. 질문에 맞는 일부 계산 경로를 골라 사용하는 전문가 혼합 구조를 쓴다. 모든 부분을 매번 계산하는 부담은 줄여도, 전체 모델을 저장하고 실행할 장비는 여전히 필요하다. 모델의 전체·활성 규모

한 번에 참고하는 자료의 최대 범위는 100만 토큰이다. 토큰은 AI가 글을 읽고 쓸 때 나누는 조각이며, 한국어 한 글자나 한 단어와 일대일로 대응하지 않는다. 코드와 설명을 길게 넣을 여유가 있다는 뜻이다. 길게 넣은 자료의 모든 항목을 정확히 찾아 쓰는 능력은 별도로 확인할 문제다.

장문의 회사 자료를 넣는다면 질문을 구체적으로 정하는 편이 결과를 확인하기 쉽다. 예를 들어 “전부 검토해 달라”보다 “반품 기한이 다른 문장을 찾아 원문 위치와 함께 비교해 달라”는 요청이 낫다. 답변을 원문과 대조할 수 있기 때문이다. 모델의 최대 입력량보다 실제로 확인 가능한 결과를 받는 방식이 업무 품질을 좌우한다.

코딩 시험은 강점과 차이를 함께 보여 준다

미니맥스가 공개한 DeepSWE v1.1 결과에서 M3.1 Flash는 73.7%였다. 이 시험은 소프트웨어 과제를 해결하는 능력을 살핀다. 아래는 같은 발표표에 실린 일곱 모델의 해당 시험 값이다. 다른 시험의 점수를 더해 하나의 종합 순위로 만들지 않았고, 회사가 취합·공개한 결과라는 성격도 유지했다. 전체 성능표와 설정

그래프는 M3.1 Flash가 이 비교에서 단독 최고라는 이야기를 하지 않는다. 같은 행에는 더 높은 모델과 낮은 모델이 함께 있다. 개발자는 자신이 하려는 일이 코드 수정인지, 문서 분석인지, 화면 조작인지부터 정하고 해당 시험을 따로 볼 수 있다. 한 종류의 시험이 빠르거나 정확하다고 모든 업무의 결과가 같아지는 것은 아니다.

시험 환경도 결과의 일부다. 공식 표는 원본 가중치 기준이며, 다른 도구를 붙이거나 타인이 압축한 파일을 쓰면 결과가 달라질 수 있다. 가벼운 변형 파일을 고른 개발자는 자기 환경에서 다시 비교할 필요가 있다.

직접 운영과 API 이용은 비용 구조가 다르다

공개 배포 폴더의 전체 크기는 약 252GB다. 주요 가중치는 여러 파일로 나뉘어 있고 실행에 필요한 코드·설정도 함께 있다. 파일 저장량은 ‘실행에 필요한 GPU 메모리의 최소값’과 다르다. 긴 자료와 여러 요청을 동시에 처리할수록 중간 계산을 보관할 공간이 더 필요해진다. 파일 구성과 용량

실행 프로그램 vLLM의 공식 안내에는 NVIDIA H100·H200 여덟 개를 쓰는 구성이 있다. 이 예시는 참고 범위를 262,144토큰으로 두고 영상 입력을 끈다. 모델 자체의 최대 100만 토큰·영상 이해 기능과, 특정 장비 설정에서 실제 켜 둔 기능을 구별해 주는 사례다. 이 문서만으로 개인 PC의 최소 장비를 제시할 수는 없다. vLLM 운영 설정

서버를 직접 준비하지 않으려면 API 경로가 있다. API는 내 프로그램이 회사 서버에 요청을 보내 답을 받는 연결 방식이다. 10월 24일 공식 요금표는 100만 토큰당 입력 0.15달러, 출력 0.60달러, 재사용 가능한 입력 캐시 읽기 0.015달러를 안내한다. 캐시는 이전에 처리한 자료를 다시 활용할 때 적용되는 별도 항목이다. 공식 API 가격

입력과 출력은 각각 사용한 양으로 계산한다. 예를 들어 입력 100만 토큰과 출력 10만 토큰을 쓰면, 위 기본 단가의 단순 합계는 0.21달러다. 캐시 적용이나 다른 유료 도구는 제외한 계산 예다. 파일을 직접 운영하는 비용과 비교할 때도 질문 한 번의 가격만이 아니라 처리량과 관리 부담을 함께 보는 편이 맞다.

상업 이용에는 표시와 통지 조건이 붙는다

공개 파일의 조건은 MiniMax Community License다. 상업 이용에는 별도 조건이 붙는다. 상업 제품·서비스에는 ‘Built with MiniMax M3.1-Flash’를 눈에 띄게 표시해야 한다. 해당 제품·서비스의 연매출이 2천만 달러를 넘으면 사전 서면 허가를 받아야 하고, 그 밖의 경우에는 일회성 통지를 보내도록 정했다. 공식 이용 조건

여기서 통지는 모델을 내려받는 행위와 다른 절차다. 공개 파일에 접근할 수 있어도, 이를 넣은 상품을 판매하거나 회사 운영에 상업적으로 연결할 때는 조건을 적용한다. 금지된 용도도 원문에 따로 적혀 있다.

한국어에 대한 별도 성능 결과는 이번에 확인한 공개표에서 찾지 못했다. 한국어 계약서나 업무 문서를 맡길 계획이라면 고유명사·숫자·표의 행을 정확히 연결하는지부터 자체 자료로 비교하는 편이 좋다. 한국어 실사용 평가는 아직 하지 않았다.

중요한 변화는 운영 선택권이 늘었다는 점이다

M3.1 Flash는 서비스로만 접근하던 모델을 파일로도 제공해 개발자의 선택지를 늘렸다. 회사 서버를 쓰면 운영이 간단해지고, 직접 운영하면 구성과 데이터 처리 경로를 더 세밀하게 정할 수 있다. 그 대가인 장비 부담과 상업 이용 조건도 함께 드러났다.

사진과 코드를 함께 읽는 능력은 작업을 시작하는 재료다. 한국 독자가 실제로 얻을 결과는 어떤 도구를 연결하고, 어느 범위까지 허용하며, 수정 결과를 어떻게 시험하느냐에 달려 있다. 이번 공개는 그 구성을 직접 선택할 수 있는 길을 하나 더 열었다.
