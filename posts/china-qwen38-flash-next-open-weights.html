알리바바 Qwen, 1,250억짜리 AI에서 매번 60억만 골라 쓴다

중국 알리바바의 AI 개발팀 Qwen이 ‘Qwen3.8‑Flash‑Next’를 공개했다. 이 모델은 1,250억 개 규모의 거대한 두뇌를 저장해 두고, 답을 한 조각 만들 때마다 약 60억 개만 골라 계산한다. 큰 AI를 더 빠르고 경제적으로 움직이려는 기술이지만, 모델 파일까지 60억 개짜리처럼 작아지는 것은 아니다.

알리바바는 중국의 전자상거래·클라우드 기업이고, Qwen은 이 회사가 만드는 AI 모델 계열이다. Qwen 팀은 중국시간 8월 26일 Qwen3.8‑Flash‑Next를 공개했다. Hugging Face와 ModelScope에는 실제 모델 파일을, GitHub에는 기술보고서와 실행 방법을 올렸다.

공개 자료에는 1,250억 개(125B)와 60억 개(6B)라는 숫자가 함께 나온다. 1,250억 개는 언어 모델 본체에 저장된 전체 파라미터 수다. 약 60억 개는 AI가 다음 글자 조각 하나를 만들 때 실제 계산에 참여하는 양이다.

파라미터는 AI가 학습하며 만든 수많은 숫자다. 이 숫자들에는 문장과 이미지에서 배운 패턴이 담겨 있다. Qwen은 전체 파라미터를 보관하면서 질문에 맞는 일부만 골라 쓰도록 설계했다.

1,250명의 전문가가 있는 회사가 요청이 들어올 때마다 관련 있는 60명만 불러 일하게 한다고 생각하면 쉽다. 매번 참여하는 인원을 줄이면 계산은 가벼워진다. 하지만 나머지 직원의 사무실과 자료까지 사라지지는 않는다.

따라서 약 60억 개라는 숫자는 파일 크기를 뜻하지 않는다. 작동하지 않는 파라미터도 저장하고 필요할 때 다른 장비로 옮겨야 한다. 계산 비용은 줄어도 디스크와 메모리, 장비 사이의 통신 부담은 큰 모델 수준으로 남는다.

이번 공개는 작은 AI의 출시가 아니라 큰 AI를 덜 움직이는 실험이다. Qwen 팀은 이 구조를 차세대 Qwen4의 예고편으로 소개했다. 실행 프로그램과 하드웨어를 만드는 회사도 정식 Qwen4가 나오기 전에 호환성을 준비할 수 있게 됐다.

1,250억 개를 저장하고 약 60억 개만 계산한다

공식 모델 카드에 따르면 언어 모델 본체는 1,250억 개(125B)이고, 토큰 하나를 처리할 때는 약 60억 개(6B)가 활성화된다. 여기에 510억 개(51B) N‑gram 임베딩과 40억 개(4B) 다중 토큰 예측 모듈이 따로 붙는다.

Qwen이 필요한 부분을 고르는 기술은 ‘전문가 혼합’이다. 영어로 Mixture of Experts, 줄여서 MoE라고 부른다. 모델 안의 여러 전문가 가운데 현재 글자 조각에 필요한 일부만 호출해 매번 하는 계산을 줄인다.

긴 문서를 읽는 방법도 바꿨다. 세 개 층이 앞에서 읽은 내용을 일정한 크기로 압축하고, 네 번째 층이 전체 문맥에서 중요한 대목을 다시 찾는다. 이 네 층 묶음이 12번 이어져 모두 48개 층을 이룬다.

기존의 전체 주의 방식은 문서가 길어질수록 앞에서 읽은 단어 사이의 관계를 많이 저장한다. 코드 저장소나 회의록이 길면 AI의 작업 메모리인 키·값 캐시도 빠르게 커진다. Qwen은 대부분의 층에서 앞 내용을 압축해 이 증가를 줄이려 한다.

압축하면 세부 정보가 사라질 수 있다. 회의록을 한 문장으로 줄이면 정확한 날짜나 사람 이름을 놓치는 것과 같다. 그래서 네 번째 층이 관련 구간을 원문에서 다시 찾아 읽는다.

압축을 담당하는 기술이 Gated DeltaNet이고, 원문을 다시 찾는 기술이 Qwen Sparse Attention이다. 이 구조가 잘 작동하면 백만 토큰 전체를 매번 같은 정밀도로 읽지 않아도 된다.

반대로 잘못된 구간을 고르면 정답이 문서 안에 있어도 놓칠 수 있다. 입력 한도가 길다는 사실과 긴 문서에서 정확한 근거를 찾는 능력은 따로 확인해야 한다.

희소 주의 층은 원문 전체를 매번 다시 읽지 않는다. 문서를 작은 블록으로 나눈 색인을 만든 뒤 512개 블록, 합계 2,048토큰을 골라 본다. 필요한 대목을 찾는 작업이 새로운 병목이 되지 않도록 범위를 제한한 것이다.

510억 개(51B) N‑gram 임베딩은 자주 함께 나오는 두세 토큰의 패턴을 따로 저장한다. 같은 표현을 매번 새로 계산하지 않고 미리 만든 표에서 찾는다. 계산은 줄지만 이 거대한 표를 보관하고 제때 불러오는 비용이 생긴다.

N‑gram 표를 GPU 밖의 시스템 메모리에 둘 수도 있다. 그러면 GPU 공간은 절약되지만, 요청이 몰릴 때 메모리에서 GPU로 데이터를 가져오는 속도가 중요해진다. 계산 부담이 메모리와 전송 부담으로 옮겨가는 셈이다.

Gated Residual은 정보를 여러 갈래로 나누고 읽기·쓰기 문을 조절한다. Qwen은 FP8로 상태를 저장하면 메모리 접근 비용이 낮아진다고 설명한다. 다른 연구팀이 같은 학습 과정을 독립적으로 재현한 결과는 아직 없다.

기본 문맥 길이는 262,144토큰이고, 회사는 YaRN을 쓰면 100만 토큰까지 늘릴 수 있다고 안내한다. 입력 상한이 커지는 것과 그 길이에서 중요한 사실을 정확히 찾는 능력은 같은 지표가 아니다.

회사가 발표한 속도는 특정 장비와 조건에서 나온 숫자다

Qwen은 100만 토큰 문맥에서 새 실행 코드의 프리필이 전체 주의보다 최대 7.6배, 디코딩이 최대 4.9배 빨랐다고 밝혔다. 접두사 캐시 적중률이 90%인 온라인 시험에서는 Qwen3.7‑Plus보다 프리필 처리량이 8.6배였다고 보고했다. 모두 회사가 정한 문맥·캐시·하드웨어 조건의 결과다.

프리필은 긴 입력을 처음 읽어 내부 상태를 만드는 과정이고, 디코딩은 그 상태에서 답을 한 토큰씩 내는 과정이다. 문서가 매우 길면 사용자는 답을 쓰는 시간보다 읽기 시작할 때의 대기를 더 크게 느낄 수 있다.

캐시 적중률 90%는 앞부분의 대부분을 다시 쓸 수 있다는 뜻이다. 같은 긴 안내문을 반복하는 서비스에서는 큰 이득이 날 수 있다. 요청마다 전혀 다른 문서를 처음부터 읽는 업무에서는 같은 배수가 나오지 않을 수 있다.

NVIDIA의 출시 당일 실험도 높은 처리량을 보였다. 다만 72개의 Blackwell Ultra GPU를 연결한 GB300 NVL72 랙에서 나온 결과다. 개인용 PC나 일반적인 H100 서버의 속도로 바꿔 읽으면 안 된다.

출시 분석은 BF16 체크포인트가 수백 GiB이고 FP8판도 170GiB를 넘는다고 계산했다. 더 낮은 정밀도로 양자화하면 줄일 수 있지만, 품질과 속도, 이미지·영상 처리 지원을 다시 측정해야 한다.

파일이 디스크에 들어간다고 빠르게 실행되는 것도 아니다. 모델 본체와 N‑gram 표를 RAM과 GPU 메모리에 어떻게 나눌지 정해야 한다. 전문가 가중치가 여러 장비로 흩어지면 장비 사이의 통신 속도도 전체 처리량을 좌우한다.

출시 첫날에는 128GB 통합 메모리 PC에서 양자화본을 실행했다는 커뮤니티 사례가 나왔다. 다만 병합 전 코드와 별도 수정이 섞인 초기 사례다. 누구나 같은 속도와 안정성을 얻는다고 일반화할 수 없다.

공식 성능표에는 강점과 약점이 함께 보인다

공급자 성능표에서 SWE‑bench Pro는 62.5, 다국어 SWE‑bench는 81.0, Toolathlon Verified는 73.5였다. Qwen이 적은 활성 계산으로 코딩과 도구 사용을 겨냥했다는 방향은 분명하다.

컴퓨터 화면을 보고 실제 작업을 수행하는 OSWorld 2.0에서는 완전 성공을 뜻하는 이진 점수가 19.4, 부분 점수가 52.3이었다. 일반 추론 점수만큼 화면 작업을 안정적으로 끝내지는 못했다.

시험 조건도 모두 같지 않다. 일부 과제는 여러 실행 도구 가운데 높은 결과를 골랐고, 일부 평가는 수정된 문제와 외부 채점 모델을 썼다. BenchLM도 공개 추적 항목 대부분이 아직 공급자 자료에 기대고 있다고 정리한다.

지금 확실한 사실은 Qwen이 긴 문맥의 계산량을 줄이는 구조와 모델 파일을 공개했다는 점이다. 모든 장비에서 더 싸고 더 정확하다고 결론 내리려면 독립 시험이 더 필요하다.

실제 도입 시험에서는 최고점보다 실패하는 방식을 봐야 한다. 긴 코드 저장소에서 같은 함수 이름을 혼동하는지, 수십 개 회의록의 날짜를 바꾸어 기억하는지, 도구 호출을 중간에 멈추는지 확인한다.

사고 수준을 낮추면 답 하나는 빨리 받을 수 있지만 복잡한 일에서 재시도가 늘 수 있다. 응답 한 번의 토큰 수보다 과제를 끝낼 때까지 걸린 총시간과 호출 횟수가 실제 비용을 더 잘 보여준다.

‘공개 가중치’여도 상업 이용 조건은 따로 있다

모델 파일을 내려받을 수 있다고 모든 사업에 자유롭게 쓸 수 있는 것은 아니다. Qwen Community License 1.0은 사용·수정·배포를 넓게 허용하면서도 사업 형태에 따라 별도 조건을 둔다. Apache 2.0과 같은 라이선스가 아니다.

외부 고객에게 모델 추론이나 미세조정을 제공하는 Model as a Service에는 별도 라이선스가 필요하다. 코딩 또는 사무 생산성을 주목적으로 하는 독립형 AI Work Assistant의 상업 이용도 같은 조건을 받는다. 회사 안에서만 쓰고 모델 기능을 고객에게 제공하지 않는 내부 이용은 예외로 적혀 있다.

월간 활성 사용자 1억 명 또는 월매출 2천만달러를 넘는 상용 제품은 모델 이름을 화면에 눈에 띄게 표시해야 한다. 이 규모보다 작은 회사라도 사업 형태가 별도 허가 대상이면 계약 검토는 필요하다.

Qwen Cloud의 API와 공개 모델 파일도 같은 상품이 아니다. API는 알리바바가 운영하는 서비스와 부가 기능을 제공하고, 공개 가중치는 사용자가 직접 서버와 실행 프로그램을 준비한다. 가격과 데이터 처리 위치, 장애 책임, 지원 범위가 모두 달라진다.

한국 스타트업이 사내 문서 검색에만 쓰는 경우와 고객에게 코딩 도우미로 판매하는 경우도 다르다. 둘 다 ‘오픈 모델 사용’으로 부를 수 있지만, 제품의 주된 목적과 고객이 모델 기능을 직접 쓰는 정도에 따라 라이선스 판단이 달라진다.

한국 기업은 속도·실패 비용·한국어를 따로 재야 한다

첫 시험에서는 실제 문서 길이로 질문을 넣고 답이 시작되는 시간과 전체 완료 시간을 잰다. N‑gram 임베딩을 시스템 메모리에 둘 때 속도가 얼마나 떨어지는지, 에이전트가 실패하고 재시도할 때 비용이 얼마나 쌓이는지도 따로 기록한다.

한국어와 이미지·영상 능력도 별도 시험이 필요하다. 다국어 코딩 점수가 높아도 국내 법률 문서의 존댓말, 표와 첨부파일, 긴 영상 속 작은 사실을 정확히 다룬다는 보장은 없다. 승인된 사내 문서로 시험 문제를 만들어 두면 모델이나 실행 프로그램이 바뀌어도 같은 기준으로 비교할 수 있다.

공식 GitHub는 Transformers, SGLang, vLLM, TokenSpeed와 OpenAI 호환 API 예제를 제공한다. 개발자는 공개 첫날부터 여러 실행 프로그램 가운데 하나를 골라 시험할 수 있다. 실제 운영에서는 정식 지원 범위와 장애 복구 방법도 성능 점수만큼 중요하다.

Qwen은 완성된 Qwen4보다 먼저 후보 구조를 공개했다. NVIDIA도 같은 날 배포 실험을 내놓았다. 새 모델 구조와 이를 돌리는 하드웨어 실험이 같은 날 공개된 것이다.

공개된 것과 공개되지 않은 것을 구분해야 한다. 모델 가중치와 구조는 볼 수 있지만, 학습 데이터 전체와 완전한 학습 과정은 나오지 않았다. 연구자가 처음부터 재현할 자유, 기업이 내부 서버에 배포할 자유, 외부 고객에게 판매할 권리는 서로 다른 문제다.

Qwen3.8‑Flash‑Next는 작은 모델이 아니라 적게 계산하도록 만든 큰 모델이다. 긴 문서를 읽을 때 계산을 줄이려는 설계지만, 도입비는 약 60억 개라는 숫자 하나로 정해지지 않는다. 저장 공간과 실제 과제 성공률, 상업 라이선스를 함께 봐야 한다.

알리바바가 공개한 것은 60억 개짜리 소형 AI가 아니다. 1,250억 개 규모의 두뇌를 보관하면서 질문마다 약 60억 개만 골라 움직이는 Qwen4의 예고편이다.
