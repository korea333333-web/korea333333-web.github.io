Kimi K3.1 Pro, 오퍼스와 3점 차…코딩·3D 실력과 실제 비용을 따져봤다

문샷 AI의 Kimi K3.1 Pro가 10월 23일 독립 평가에서 55점으로 상위권에 올랐다. 오퍼스 5.5와는 3점 차이다. 코딩과 자료 작업을 맡길 AI를 고를 때, 키미를 다시 비교해 볼 만한 변화다. AA의 출시 평가

키미는 질문에 답하는 대화형 AI이면서, 프로그램을 실행하고 파일을 만들어 일을 마치는 기능도 제공한다. 이번 모델은 웹·앱과 업무용 Kimi Work, 코딩 도구, API에 제공된다. API는 다른 프로그램이 AI에 요청을 보내는 연결 창구다. 직접 설치에 필요한 모델 가중치는 11월 4일까지 공개할 예정이어서, 서비스 출시와 파일 공개 시점은 구분해야 한다. 문샷 AI 공식 발표

핵심은 ‘오퍼스를 이겼다’는 한 줄보다 어떤 일을 얼마나 잘 끝내는지다. 독립 평가, 회사의 자체 시험, 영상 제작자의 개인 시험은 물어보는 문제가 다르다. 이 글에서는 세 자료를 나눠 보고, 웹페이지 제작과 3D 작업을 하려는 사용자가 실제로 확인할 지점까지 연결했다.

독립 평가 55점, 오퍼스와의 차이는 3점

AA가 발표한 키미의 순위는 모델별 4위다. 평가 화면의 줄 수를 세어 순위를 다시 매기면 안 된다. 같은 모델이 설정별로 여러 번 나타날 수 있기 때문이다.

종합 점수는 정답률과 다르다. AA는 여러 종류의 시험을 묶어 지수를 만든다. 55점은 ‘사용자 질문의 55%를 맞힌다’는 뜻이 아니며, 3점 차이를 사람의 작업 시간 차이로 바로 바꿀 수도 없다. 한 숫자는 후보를 좁히는 출발점이고, 실제 선택은 자신이 맡길 과제에서 다시 확인해야 한다.

AA의 평가 방법에 따르면 현재 지수는 업무 수행, 코딩, 과학 추론, 일반 능력의 네 분야에 속한 10개 시험을 합친다. 주로 영어·텍스트 중심이며 다국어 능력은 별도로 평가한다. 한국어 제안서의 말투나 국내 자료 검색이 중요한 독자는 이 순위에 더해 자신이 쓰는 한국어 자료로 비교할 필요가 있다.

모델명 옆 설정도 비교의 일부다. 더 오래 생각하게 한 결과와 빠른 응답을 우선한 결과는 같은 서비스 안에서도 다를 수 있다. K3.1 Pro의 API는 생각의 강도를 low·high·max로 조절하며 기본은 max다. 반복적으로 쓰는 간단한 요청과 어려운 설계 과제에 모두 같은 설정이 필요한지는 따로 시험할 수 있다. 공식 추론 설정 안내

회사 점수와 독립 점수가 다른 이유

회사가 제시한 코딩 점수는 아래와 같다. 키미는 Claude Code 실행 환경을 사용했고, 타사 값은 공개된 최고 결과를 가져왔다. 한 자리에서 모두 같은 조건으로 다시 측정한 표는 아니다.

AA도 Terminal-Bench 4.0을 평가하지만 mini-swe-agent라는 다른 실행 도구를 쓴다. 66개 과제를 각각 세 번 반복해 평균을 낸다고 설명한다. 회사 표에 AA의 결과를 끼워 넣으면 이런 조건 차이가 가려진다. 비교할 때는 숫자 앞에 ‘누가, 어떤 도구로 측정했는가’를 붙여 읽는 편이 정확하다. AA의 코딩 시험 방법

여기서 실행 환경은 모델이 받은 답을 실제 명령과 파일 수정으로 이어 주는 도구 묶음이다. 같은 모델도 어떤 도구를 쓸 수 있는지, 실패 후 다시 시도할 시간이 얼마나 있는지에 따라 완성도가 달라진다. 개발자가 고를 대상 역시 모델 하나만이 아니라 모델과 코딩 도구의 조합이다.

BenchCAD는 여러 방향에서 본 그림을 바탕으로 3D 형상을 다시 만드는 시험이다. 형상이 얼마나 겹치는지 측정한 값이므로, 표의 92.7%를 ‘판매할 제품의 92.7%가 완벽하게 완성된다’고 해석할 수는 없다. 치수, 조립 가능성, 인쇄 안정성처럼 실제 제작에 필요한 조건은 결과물에서 따로 검사해야 한다.

3D Make와 업무 앱에서는 무엇을 할 수 있나

공식 안내의 3D 작업은 그림 한 장을 그리는 기능과 다르다. 글이나 스케치·참고 이미지를 받아 형태를 추론하고, Blender나 CAD 같은 입체 설계 도구의 스크립트를 작성·실행한다. 파라미터 방식은 가구의 폭·높이처럼 수치를 바꾸며 모양을 조정하는 작업을 뜻한다. 공식 모델·3D 기능 안내

웹과 앱의 3D Make는 모델을 온라인에서 미리 보고 편집하는 기능으로 소개됐다. 3D 인쇄용 파일 다운로드와 영상·Live Photo 내보내기도 안내돼 있다. 무엇이 만들어지는지 보고 싶은 독자는 공식 발표의 3D Modeling and Design 시연 구간과 공식 3D Make 화면 원본에서 확인할 수 있다. 회사가 공개한 사례이며 편집부가 직접 생성한 결과는 아니다.

예를 들어 매장에서 쓸 작은 진열대를 구상한다면, 첫 요청에서 폭·깊이·높이와 선반 수를 함께 적는 방식으로 시험해 볼 수 있다. 이어서 ‘전체 폭은 유지하고 가운데 선반 높이만 바꿔 달라’고 요청하면 수정 능력도 비교할 수 있다. 이는 독자를 위한 시험 예시다. 외형이 그럴듯한지와 지정한 치수를 지키는지는 각각 확인할 항목이다.

업무용 Kimi Work는 웹 대화보다 컴퓨터 안의 파일 작업에 초점을 맞춘 앱이다. 공식 제품 페이지는 허용한 폴더의 문서 처리, 브라우저 작업, 예약 실행을 설명한다. 파일을 덮어쓰거나 코드를 실행하기 전 승인을 받는 Ask before acting 설정도 제공한다. 중요한 원본 대신 복사본이 있는 작업 폴더로 처음 범위를 정하면 변경 결과를 대조하기 쉽다. Kimi Work 기능·권한 안내

예약 실행도 실제 업무에서는 별도 조건을 봐야 한다. 공식 FAQ는 밤새 작업하려면 컴퓨터를 깨워 두는 설정을 켜라고 안내한다. ‘내일 아침까지 정리해 줘’라는 문장만으로 컴퓨터의 전원 상태까지 해결되지는 않는다. 파일 접근, 실행 시간, 결과 저장 위치를 한 번에 정해야 다음 날 무엇이 끝났는지 확인할 수 있다.

해외 영상 평가 두 편은 결론이 조금 다르다

Arena 채널이 10월 23일 올린 Peter Gostev의 첫인상 영상은 K3보다 크게 좋아졌지만, 해당 시험에서는 최상위 수준에 완전히 닿지는 않았다고 설명한다. 3D 장면, HTML 애니메이션, 웹사이트와 자료 조사 화면을 비교하는 구성이다. 아래 인용은 공개 영상 설명과 구간 목록 기준이며, 전체 영상을 재생하거나 자막 전체를 검수한 평가는 아니다.

이 영상에는 중요한 가격 정정이 붙어 있다. 촬영 당시 K3.1 요금이 없어 영상의 비용을 K3 요금으로 계산했으며, 실제 K3.1 비용은 약 3분의 1 낮다고 설명한다. 화면에 나온 옛 가격을 그대로 가져와 현재 모델의 비용 경쟁력을 판단하면 불리하게 평가할 수 있다. 제작자가 덧붙인 가격 안내

Peter가 공개한 3D 요청문 모음에는 큰 도시, 움직이는 장면, 게임형 공간 등 다양한 과제가 담겨 있다. 로마 도시 요청문만 해도 건물 배치와 카메라 조작, 외부 파일 없이 실행하는 조건을 함께 지정한다. 영상의 멋진 한 장면만 보는 것보다 요청문에서 무엇을 요구했는지 살피면, 화면의 화려함과 지시 이행을 구분하기 쉬워진다.

Matt Johnston | AI Engineer 채널의 10월 24일 영상은 더 긍정적이다. 제작자는 자신의 아홉 개 시험에서 97/100점, 전체 네 번째, 자신이 시험한 공개형 모델 중 가장 좋은 결과라고 설명한다. 전체 실행 비용은 약 4.84달러, 과제당 0.54달러로 제시했다. 이는 해당 제작자의 시험·채점·비용이며 AA의 점수나 일반 사용자의 평균 요금과 같은 기준이 아니다. 영상 설명 원문

두 의견은 모순이라기보다 다른 과제를 보는 두 창에 가깝다. 첫 영상은 장면의 완성도와 경쟁 모델 대비 인상을 설명하고, 두 번째는 제작자가 정한 아홉 과제의 점수를 제시한다. 개인 채점의 97점과 독립 종합 지수의 55점을 같은 막대그래프에 올리면 안 된다. 자신이 만들 결과물과 비슷한 구간을 골라 보는 쪽이 모델 선택에 도움이 된다.

단가는 내려갔지만 작업 한 번의 비용은 따로 본다

AA가 확인한 기본 API 단가는 100만 토큰당 입력 2달러, 출력 10달러, 캐시 적중 입력 0.20달러다. 토큰은 AI가 글을 읽고 만들 때 나누는 작은 단위이며 글자 수와 정확히 같지는 않다. 캐시는 이미 처리한 입력을 재사용하는 기능이다. 이 가격은 웹 구독료나 Highspeed 요금으로 읽으면 안 된다. 출시 시점 가격 확인

AA의 종합 시험에서는 과제당 비용이 약 1.98달러로 K3와 비슷했다. 토큰 단가는 33% 낮아졌지만 출력량은 약 4만 8천에서 5만 5천 토큰으로 늘었다. 이 평균 비용을 한 번의 짧은 대화 요금으로 쓰거나, 단가 인하율만 보고 모든 작업이 같은 비율로 싸졌다고 계산하면 실제 사용량을 놓친다.

공식 API 가격 안내도 입력과 출력의 사용량에 따라 청구하며 Kimi 회원제·Kimi Code 구독과 구별한다고 설명한다. 단순 계산 예로, 캐시 없이 입력 10만 토큰과 출력 1만 토큰을 썼다면 위 기본 단가에서 각각 0.20달러와 0.10달러다. 합계 0.30달러는 그 두 항목만 계산한 예시로, 실제 작업 기록이나 도구 사용료까지 재현한 견적은 아니다.

개발자가 봐야 할 값은 요청 한 번의 단가보다 완성된 결과물 한 개의 비용이다. 첫 결과를 고치는 횟수, 실패 후 다시 실행한 요청, 사람의 수정 시간까지 기록하면 차이가 드러난다. 웹페이지 하나를 만드는 데 저렴한 모델은 여러 번 수정해야 하고 다른 모델은 한 번에 끝날 수도 있다. 반대 상황도 있으므로 같은 요청과 같은 완료 기준을 먼저 정해야 한다.

지금 쓰는 서비스와 나중에 공개될 모델 파일

공식 출시 안내는 Kimi Work 3.1.0 이상을 Windows와 Apple silicon Mac에서 이용하도록 설명한다. Kimi Code에서는 /model 명령으로 모델을 고른다. 조직용 계정은 출시 시 기본 접근이 꺼져 있어 관리자가 활성화해야 한다. 계정별 사용량과 웹·앱 구독 조건은 별도 요금 화면에서 확인해야 하며, 이번 기사에서는 한국 계정의 결제나 생성까지 시험하지 않았다.

‘공개 가중치’는 학습된 모델의 계산용 값을 내려받아 자신의 환경에서 실행할 수 있게 한다는 뜻이다. 학습 자료와 개발 과정까지 모두 공개한다는 말과도 다르다. AA 역시 공개 가중치와 엄격한 의미의 오픈소스를 구분한다. 10월 24일 확인 기준으로 K3.1 Pro의 가중치와 이용 허락 조건은 아직 공개되지 않았으므로, 기업이 직접 설치할 수 있는 범위는 공개 후 다시 확인해야 한다. AA의 공개 모델 용어 정의

모델 파일을 받을 수 있게 되는 것과 개인 컴퓨터에서 편하게 돌아가는 것도 별개의 문제다. 실제 장비 선택에는 파일 크기, 계산에 필요한 메모리, 지원 프로그램과 처리 속도 정보가 필요하다. 현재 서비스에서 결과물을 시험해 보는 단계와 사내 설치를 설계하는 단계를 나누면, 공개 예정이라는 표현 때문에 필요한 준비를 앞당겨 확정하는 일을 줄일 수 있다.

한국어 웹·3D 제작자라면 이렇게 비교하면 된다

첫 시험은 너무 큰 프로젝트보다 수정 전후를 확인할 수 있는 작은 결과물이 좋다. 웹 제작이라면 같은 한국어 상품 설명과 가격표를 주고 휴대전화용 판매 페이지를 만들게 한다. 버튼 동작, 가격 누락, 글자 잘림을 확인한 뒤 수정 요청을 한 번 더 보낸다. 이 글에서 제안하는 비교 절차이며, 키미와 오퍼스로 직접 수행한 결과는 아니다.

3D 제작이라면 앞에서 제안한 진열대처럼 치수를 검증할 수 있는 대상을 고른다. 출력 파일을 받았는지, 지정한 치수가 유지됐는지, 수정한 부분 외에 다른 곳이 망가지지 않았는지를 기록한다. 멋진 첫 화면과 계속 편집할 수 있는 파일은 서로 다른 성과다. 현장에서 쓸 수 있는지는 두 번째 수정까지 해 봐야 더 분명해진다.

자료 조사 기능은 근거 연결을 별도로 확인하면 된다. 모델에게 결론만 요구하지 말고 숫자의 출처 문서와 해당 항목을 함께 제시하도록 요청한다. 사람이 원문과 숫자를 대조하는 시간을 기록하면 작성 속도뿐 아니라 검수 부담도 비교할 수 있다. 특히 한국어 표현을 자연스럽게 고치는 일과 출처가 맞는지 확인하는 일은 따로 채점하는 편이 좋다.

이번 변화는 키미가 모든 작업에서 오퍼스를 앞섰다는 선언보다, 실제 후보 목록에 들어갈 만큼 격차를 줄였다는 데 의미가 있다. 독립 지수는 가까워졌고 코딩·3D 기능은 시험할 통로가 열렸다. 이제 선택의 기준은 가장 큰 홍보 숫자보다, 내가 쓰는 자료로 결과를 끝내고 수정하는 데 드는 비용과 시간이다.

자료 확인일은 2026년 10월 24일이다. 수치와 이용 조건은 공식 문서·독립 평가를 대조했고 영상은 원본 설명·공개 구간 정보와 확인 가능한 요청문을 참고했다. 모델 직접 실행, 두 영상 전체 재생, 자막 전체 검수는 하지 않았다. 그래프·표는 확인한 수치를 자체 재구성했으며 공식 시연은 원문 링크로 구분했다.
